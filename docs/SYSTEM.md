# System handoff: what cachy-setup installed and configured

Reference for Claude Code (and humans) tweaking this machine after install. It describes the
state that `install.sh` / `post-install.sh` produce, where every piece lives, which module owns
it, and how to change it without breaking the rest.

> **This is a description of intent, not a live readout.** Before changing something, check the
> real state (commands in [§12 Diagnostics](#12-diagnostics-and-logs)). If the system and this
> document disagree, trust the system and update this file.

## 0. Rules for making changes

1. **Make changes reproducible.** The setup is meant to be rebuildable from the repo.
   - **Working copy:** `~/Cachy` is a git clone, copied there by `install.sh`. If it's missing:
     `git clone https://github.com/OhBoyItsFrancis/Cachy ~/Cachy`.
   - **Deployed copy:** `/opt/cachy-setup` is root-owned, has no `.git`, and is what gets run.
   - **Workflow:** change the module in the working copy (e.g. `~/Cachy/modules/40-gaming.sh`),
     commit, deploy, then re-run that module:
   `sudo rsync -a --exclude .git ~/Cachy/ /opt/cachy-setup/ && sudo /opt/cachy-setup/post-install.sh 40-gaming`.
   Editing files in `/etc` by hand is fine for experiments, but the next module run overwrites any
   file marked `Managed by cachy-setup`.
2. **Modules must stay idempotent.** Running any module twice must give the same result: replace
   files rather than appending to them, and use `grep -q … ||` before adding lines. Use the
   helpers in `lib/common.sh` (§3).
3. **Careful areas.** A mistake here can leave the machine without a desktop or unbootable:
   - the kernel command line (`add_kernel_params` and the bootloader regeneration)
   - `/etc/X11/xorg.conf.d/10-cachy-gpu.conf`, which is owned by `cachy-vfio-mode`
   - the libvirt hook and `vfio-prepare.sh` / `vfio-release.sh` (they stop the display manager)
   - `/etc/modprobe.d/cachy-nvidia.conf`

   Read §8.7 before touching the VFIO pieces. Keep `linux-cachyos-lts` installed as the fallback
   boot entry.
4. **Don't duplicate CachyOS defaults.** `cachyos-settings` already tunes sysctls, zram, I/O
   schedulers, THP, ntsync, NVIDIA/AMD modprobe options and journald (§2). Override them in a
   later-sorted drop-in rather than editing CachyOS's files, which updates overwrite.
5. **Test before deploying:** `sudo tests/sandbox-test.sh` (the whole post-install with stubs),
   `python3 -m unittest tests/test_cachy_vm.py`, and the `shellcheck` command in the README.
   Add an assertion to `tests/sandbox-test.sh` for every new behaviour.
6. **Snapshots exist.** snap-pac takes pre/post btrfs snapshots of every pacman transaction, and
   they can be booted from the Limine menu. Before risky manual changes, take one yourself:
   `sudo snapper -c root create -d "before <change>"`.

## 2. Base OS (from CachyOS's installer, stage 1)

- **Installer:** `cachyos-installer` (package `cachyos-cli-installer-new`) in headless mode. The
  settings JSON is generated by `install.sh` and deleted afterwards.
- **Disk:**
  - `TARGET_DISK` p1 = ESP (vfat, `ESP_SIZE`, default 2G), mounted at `/boot`.
  - p2 = btrfs with subvolumes `@` `/`, `@home`, `@root`, `@srv`, `@cache` (`/var/cache`),
    `@tmp`, `@log` (`/var/log`).
  - Plus a nested subvolume `/var/lib/libvirt/images` (created by 70-virtualization, NOCOW,
    excluded from root snapshots).
- **Bootloader:** Limine. The kernel command line lives in `/etc/default/limine`
  (`KERNEL_CMDLINE[default]=…`); `limine-mkinitcpio` regenerates initramfs and entries;
  `limine-snapper-sync` adds snapshot entries.
- **Kernels:** `linux-cachyos` (BORE scheduler, the default entry) and `linux-cachyos-lts` (fallback).
- **Repos:** `cachyos-znver4`, `cachyos-core-znver4`, `cachyos-extra-znver4`, `cachyos`, plus
  Arch `core`/`extra`/`multilib`. 10-base sets ParallelDownloads=10 and Color.
- **Drivers:** `chwd -a` (NVIDIA open + Mesa for the iGPU).
- **Desktop:** CachyOS's `cinnamon` profile (cinnamon, lightdm, gnome-terminal, …) plus CachyOS's
  base desktop set: PipeWire, NetworkManager, bluez, cups, ufw, fonts, firefox, alacritty,
  octopi, paru.
- **Shell:** fish with `cachyos-fish-config`.
- **CachyOS defaults to leave alone or override with drop-ins** (package `cachyos-settings`):
  - `/usr/lib/sysctl.d/70-cachyos-settings.conf`: swappiness 100 (150 with zram), dirty bytes,
    `vfs_cache_pressure` 50, nmi_watchdog 0, …
  - zram-generator, I/O schedulers (kyber for NVMe), THP defrag, `ntsync` module load
  - `/usr/lib/modprobe.d/nvidia.conf` (`NVreg_InitializeSystemMemoryAllocations=0`)
  - watchdog blacklists, journald size, the `game-performance` helper

## 3. The repo and the pipeline

```
install.sh            live ISO: preflight → settings JSON → cachyos-installer → mount target
                      (mount --all --fstab …/etc/fstab --target-prefix /mnt) → rsync repo to
                      /mnt/opt/cachy-setup → arch-chroot post-install.sh --chroot
post-install.sh       runs modules/[0-9]*.sh in order; each in its own subshell with errexit;
                      failures are reported and the remaining modules still run. Args: module
                      names to run only those, --list, --chroot.
lib/common.sh         helpers (below)
modules/NN-name.sh    one concern each (sections 4–8)
bin/                  user commands, copied to /usr/local/bin
files/                static files installed by modules (hooks, units)
docs/                 install-guide.md, steam-launch-options.md, this file
tests/                sandbox-test.sh + stubs/, test_cachy_vm.py
config.example.env    every variable with defaults; config.env (git-ignored) overrides it
```

`load_config` sources `config.example.env` first and then `config.env`, so new variables get
defaults automatically.

Target user: `CACHY_USER` (set by install.sh), else config `USERNAME` if that user exists, else
`$SUDO_USER`. Never take `$USERNAME` from the environment: sudo sets it to root.

**Helpers** (always use these in modules):

| Helper | Does |
|---|---|
| `pkg_install a b …` | `pacman -S --needed --noconfirm`. If the group fails it retries one by one; packages still failing get one more try after `cachyos-rate-mirrors` (once per run) and `pacman -Syyu`. If pacman then reports `installing X breaks dependency … required by Y` (a split package only partly synced on the mirror), it installs Y from the same repo as X. Final failures go to `$CACHY_STATE/failed`, and the warning includes pacman's own `error:` lines. |
| `aur_install a …` | builds with `paru` as the user, using a temporary NOPASSWD sudoers file (`/etc/sudoers.d/99-cachy-setup-aur`) that is always removed |
| `svc_enable` / `svc_disable` | `enable` (adds `--now` when not in a chroot) / `disable` + `stop` |
| `user_svc_enable` | `systemctl --global enable` (for all users) |
| `write_file DEST [MODE] <<EOF` | creates parent dirs and writes the file |
| `install_file SRC DEST [MODE]` | copies from `files/` |
| `add_kernel_params "k=v …"` | merges params into the Limine / sdboot-manage / GRUB cmdline (replaces same-key params, so it is idempotent) and flags a boot regeneration, which post-install runs once at the end |
| `detect_gpu_pci`, `detect_igpu_pci`, `detect_usb_controller_pci`, `pci_to_xorg_busid` | PCI helpers |
| `in_chroot`, `is_true`, `as_user`, `info`/`ok`/`warn`/`die` | misc |

## 7. Kernel command line and boot

- Added: `amd_iommu=on iommu=pt`, and `mitigations=off` only if opted in. Everything else comes
  from CachyOS (`quiet splash nowatchdog`, root= …).
- To change it: use `add_kernel_params` in a module, or edit `KERNEL_CMDLINE[default]` in
  `/etc/default/limine`, then run `sudo limine-mkinitcpio`.
- Not used on purpose: `vfio-pci.ids=` / early vfio binding. Passthrough is dynamic, so the 3080
  stays usable on the host. `pcie_acs_override` is only a last resort (§8.7).
- Initramfs: chwd removes the `kms` hook for NVIDIA (`/etc/mkinitcpio.conf.d/10-chwd-kms.conf`).

## 8. Subsystems

### 8.1 NVIDIA
- Open kernel modules from `chwd` (`linux-cachyos-nvidia-open`, `linux-cachyos-lts-nvidia-open`)
  and `nvidia-utils`.
- `nvidia_drm modeset=1 fbdev=1`: nvidia-drm owns the console framebuffer, and the single-GPU
  hook relies on that.
- Suspend: PreserveVideoMemoryAllocations + the three nvidia-* services; the save file goes to `/var/tmp`.
- Overclocking, power limit and fans go through LACT (`lactd`). LACT holds `/dev/nvidia*`, so the
  VFIO hook stops it.
- X11 only: Cinnamon runs on Xorg here. Cinnamon's Wayland session is experimental and wasn't set up.

### 8.2 CPU and power
amd-pstate EPP driven by power-profiles-daemon. First boot sets the `performance` profile
(`PERFORMANCE_PROFILE`). GameMode switches the governor to `performance` while a game runs.
`game-performance %command%` (from CachyOS) is an alternative that uses ppd. `cpupower` is
installed but not configured.

### 8.3 Desktop
Cinnamon on LightDM + slick-greeter, with Papirus-Dark and Adwaita-dark, a flat mouse
acceleration profile, and fish as the login shell. PipeWire handles audio. JACK apps use `jack2`;
switching to `pipewire-jack` means replacing `jack2` (`sudo pacman -S pipewire-jack`, answer *y*).

### 8.4 Gaming
CachyOS kernel (BORE), `ntsync`, proton-cachyos, GE-Proton, GameMode, MangoHud, Gamescope,
ananicy, and the sysctls/env from §5. Things left out on purpose: a global `PROTON_ENABLE_NVAPI`
(recent Proton enables NVAPI itself), `mitigations=off` by default, and an active sched_ext
scheduler.

### 8.5 Apps
See §4 50-apps. Things updated outside pacman: JetBrains IDEs (Toolbox), the Spotify client
(spotify-launcher), GE-Proton (`cachy-ge-proton`).

### 8.6 AI / Claude Code
- **Cloud:** `claude` CLI and Claude Desktop, both pacman-managed. Updates come with `paru`, so
  don't use the native installer or `npm -g` copies on top.
- **Local:** `ollama.service` on the 3080 serves on `127.0.0.1:11434`, with the settings from the
  §5 drop-in.
- **`claude-local [--model M] [claude args]`:**
  - It sets `ANTHROPIC_BASE_URL=http://127.0.0.1:11434`, `ANTHROPIC_AUTH_TOKEN=ollama`,
    `ANTHROPIC_MODEL` and the per-tier `ANTHROPIC_DEFAULT_*_MODEL` vars, then `exec`s `claude`.
    This uses Ollama's Anthropic-compatible API (Ollama ≥ 0.14).
  - It pulls the model on first use.
  - It only affects that process, so the normal `claude` login is untouched.
- **Default model:** `OLLAMA_MODEL`, `qwen3-coder:30b`, a MoE model that partly offloads to RAM
  on 10 GB VRAM. It is pulled on first boot.
- Ollama is stopped while the passthrough VM owns the GPU, and restarted afterwards.
- MCP-friendly tooling: `nodejs`/`npm` (for `npx`), `uv` (for `uvx`), `github-cli`, `bubblewrap`.

### 8.7 VFIO / GPU passthrough (read before editing)

**Modes** (`MODE` in `/etc/cachy-vfio.conf`, switched with `sudo cachy-vfio-mode single|hybrid`):

| | single | hybrid |
|---|---|---|
| Monitor cable | RTX 3080 | motherboard HDMI/DP (iGPU) |
| `10-cachy-gpu.conf` | `AutoAddGPU false` + Device `nvidia` BusID of `GPU_PCI` | `AutoAddGPU false` + Device `modesetting` BusID of `IGPU_PCI` |
| VM start | stops display-manager, unbinds VT consoles + efi/simple framebuffer, kills leftover `/dev/nvidia*` users | refuses to start (rolls back) if any process still uses `/dev/nvidia*` |
| Host gaming | full 3080 | iGPU only (PRIME offload doesn't work with AutoAddGPU false) |

`AutoAddGPU false` is what keeps Xorg off the GPU that isn't meant to drive the session. In
hybrid mode that is what makes hot hand-over possible.

**Flow:**
```
libvirt start ──► /etc/libvirt/hooks/qemu <dom> prepare begin   (domain XML on stdin)
   acts only if <dom> ∈ VM_NAMES AND the XML contains the GPU's bus/slot address
   └► vfio-prepare.sh: start libvirt-nosleep@<dom>
                       → stop active GPU_SERVICES (recorded in /run/cachy-vfio/stopped-services)
                       → [single] stop DM (recorded), unbind vtcons (recorded), unbind boot fb
                       → kill (single) / refuse (hybrid) remaining /dev/nvidia* users
                       → modprobe -r nvidia_drm nvidia_modeset nvidia_uvm nvidia (5 retries)
                       → modprobe vfio-pci
                       → AllowedCPUs=HOST_CPUS on user.slice, system.slice, init.scope
                       (any failure → vfio-release.sh rollback, exit 1 → libvirt aborts the start)
libvirt binds the hostdevs (managed='yes') to vfio-pci, VM runs
VM stops, libvirt re-attaches the devices ──► hook release ──► vfio-release.sh:
                       restore AllowedCPUs → modprobe nvidia stack → [single] rebind vtcons,
                       start DM → restart recorded services → stop nosleep → rm /run/cachy-vfio
```

**Invariants (don't break these):**
- Never unload `drm`, `drm_kms_helper` or `amdgpu`; the iGPU needs them. The original ilayna
  scripts do unload them. Don't copy that back in.
- Hooks must never call `virsh` or the libvirt API (it deadlocks). Device detach is libvirt's
  job via `managed='yes'`.
- `vfio-release.sh` must stay idempotent: it can run twice (rollback, then libvirt's release).
- Every service that opens `/dev/nvidia*` must be listed in `GPU_SERVICES` (currently
  `ollama.service lactd.service nvidia-persistenced.service`). If you add something like that
  (e.g. a CUDA container, a monitoring daemon), add it there.
- The GPU check in the hook greps for `<address domain='0x0000' bus='0xBB' slot='0xSS'`. If you
  change how `cachy-vm` writes hostdevs, keep `test_hook_matches_generated_hostdev` passing.

**VM** (from `cachy-vm create`, default name `win11`):
- **Firmware and machine:** Q35, OVMF with Secure Boot and enrolled keys (`firmware='efi'`
  auto-select), TPM 2.0 (`tpm-crb`, swtpm), SMM.
- **CPU:** host-passthrough with `topoext` and cache passthrough. Topology is 7 cores × 2
  threads; vCPUs are pinned to SMT sibling pairs of cores 1–7, and the emulator and iothread to
  `HOST_CPUS` (0,8).
- **Hyper-V enlightenments:** relaxed, vapic, spinlocks, vpindex, runtime, synic, stimer, reset,
  vendor_id, frequencies, tlbflush, ipi. Also `kvm hidden`, hypervclock, and no HPET.
- **Disk and network:** `/var/lib/libvirt/images/win11.qcow2`, virtio with `cache=none`,
  `io=native`, `discard=unmap` and an iothread; virtio network on the `default` NAT network.
- **No memballoon.** No hugepages either: THP covers it, and static hugepages would be a possible
  tweak.
- **`cachy-vm passthrough on`** removes SPICE graphics, video, the spicevmc channel, sound and the
  USB tablet, sets video to `none`, and adds hostdevs for every function in the GPU's slot (the
  ROM file goes on function 0 if `GPU_ROM_FILE` is set) and for `USB_CONTROLLER_PCI` if enabled.
  `off` reverses it. It is idempotent; edits go through `virsh dumpxml --inactive` → ElementTree →
  `virsh define`.
- Logs go to `/var/log/libvirt/cachy-vfio.log`; libvirt's own QEMU log is
  `/var/log/libvirt/qemu/win11.log`.

**IOMMU groups:** `cachy-vfio-check` shows them. If the USB card shares a group with other
devices, move it to another slot first. `pcie_acs_override=downstream,multifunction` (the CachyOS
kernel carries the patch) is the last resort, because it weakens isolation.

### 8.8 First boot (`cachy-firstboot.service`)
A one-shot service after network-online, libvirtd, ollama, tailscaled and ppd. It writes
`/var/lib/cachy-setup/firstboot.done` only if every step succeeded, otherwise it retries on the
next boot. Steps:

1. ufw rules: allow in on virbr0, route in/out on virbr0, allow in on tailscale0, 41641/udp
2. libvirt `default` network: define if missing, autostart, start
3. `powerprofilesctl set performance`
4. `tailscale set --operator=$USER`
5. GE-Proton, if it isn't installed yet
6. `ollama pull $OLLAMA_MODEL`

To re-run it: `sudo rm /var/lib/cachy-setup/firstboot.done && sudo systemctl start cachy-firstboot`.

## 11. Recipes

**Add a repo package to the setup:** add it to the right `pkg_install` line in the module,
deploy, run the module. For an AUR package use `aur_install`, and keep the number of AUR packages
small. To check whether a package is in the repos first: `pacman -Si name` / `paru -Si name`.

**Change a sysctl:** edit the module's `write_file /etc/sysctl.d/80-cachy-*.conf` block, then run
the module and `sudo sysctl --system`. To override a CachyOS value, use a file sorting after
`70-cachyos-settings.conf` (e.g. `80-…`/`99-…`) in `/etc/sysctl.d`.

**Change kernel parameters:** in 20-hardware, `add_kernel_params "…"`. post-install regenerates
the boot entries at the end; then reboot and check `/proc/cmdline`. If a param breaks boot, pick
the `lts` entry or a snapshot in Limine, then fix `/etc/default/limine` and run `sudo limine-mkinitcpio`.

**Add a GPU-using service** (e.g. a CUDA container or ComfyUI): add its unit to `GPU_SERVICES` in
70-virtualization (the variable near the top of the passthrough config section) and re-run 70.

**Pass another device to the VM:** add its PCI address to the hostdev list in
`bin/cachy-vm` (`cmd_passthrough`) or temporarily use `virt-manager`. Check its IOMMU group first.

**Change VM resources:** set `VM_MEMORY_GB` / `VM_VCPU_CORES` / `HOST_CPUS` in `config.env` and
re-run 70. This only affects *new* VMs; for an existing VM use `virsh edit win11` or recreate it.

**Add a new module:** create `modules/NN-name.sh` (`# shellcheck shell=bash`, use the helpers,
end with `ok "…"`), add assertions to `tests/sandbox-test.sh` (and stubs if it calls new
commands), and document it here.

**Move to a Wayland session later:** Cinnamon Wayland is experimental. The VFIO single mode
assumes a display manager plus Xorg, so `cachy-vfio-mode` and the prepare hook's process checks
would need updating.

## 13. Known limitations and things not verified on the real hardware

- **Only simulated:** the whole pipeline was tested in a sandbox with stubbed pacman, systemctl
  and lspci, and the VM tool with unit tests. The first real run may surface issues, especially:
  - the headless installer's behaviour on the ISO's version
  - the `limine-snapper-sync` unit name
  - `glib-compile-schemas` accepting every key in the override
  - **Half-synced CachyOS mirrors (seen on the first real install).** `cinnamon` and
    `network-manager-applet` failed with
    `installing libnma-common (1.10.6-3) breaks dependency 'libnma-common=1.10.6-3.1' required by libnma-gtk4`.
    The mirror's `cachyos-extra-znver4` had CachyOS's `libnma-gtk4` but not the matching `libnma` /
    `libnma-common`, so pacman took Arch's at a different pkgrel. `pkg_install` now re-ranks mirrors
    and aligns such sets automatically. By hand: `sudo cachyos-rate-mirrors && sudo pacman -Syyu`, or
    install the whole set from one repo (`sudo pacman -S extra/libnma extra/libnma-common extra/libnma-gtk4`).
- `detect_usb_controller_pci` gives up if there are zero or several non-AMD USB controllers; then
  `USB_CONTROLLER_PCI` must be set by hand.
- MSI BIOS menu paths in the docs are typical, not confirmed for this board's BIOS version.
- Hybrid mode: host games run on the iGPU. There is no PRIME offload while `AutoAddGPU false`.
- No Looking Glass, no evdev input passthrough, no static hugepages, no CPU governor switching in
  the hooks: all are candidates below.
- Anti-cheat games with kernel drivers generally won't run on Linux or in the VM.

## 14. Tweak backlog (ideas, not implemented)

- **Static hugepages** for the VM (allocate 8192 × 2 MiB in prepare, free in release) and
  `<memoryBacking><hugepages/>`.
- **Looking Glass** (AUR `looking-glass`) for hybrid mode: view the VM in a window on the iGPU
  desktop instead of switching monitor inputs.
- **Evdev passthrough** of a keyboard and mouse with a toggle key, as an alternative to the USB card.
- **sched_ext:** try `scx_lavd` (gaming) via scx-manager / `scx_loader`, and benchmark against BORE.
- **`nct6687d-dkms`** (AUR) for board fan/VRM sensors, then fan curves in CoolerControl.
- **NVIDIA:** a persistent power limit / undervolt profile in LACT.
- **Secure Boot on the host** with `sbctl` (signed Limine/UKIs), so the BIOS can keep Secure Boot
  on (useful if you ever dual-boot Windows for anti-cheat that requires it). The VM already has
  its own Secure Boot via OVMF.
- **Wayland:** revisit when Cinnamon's Wayland session matures (would need VFIO hook changes, §11).
- **Flatpak** versions of apps if repo packages lag (Flathub is already configured).
- **Backups:** `btrbk` or `snapper` send/receive of `@home` to the second NVMe drive or a NAS.
